# Methodology

Measured results are in [results.md](results.md), which is generated by
`python -m training.evaluate`. This document explains how those numbers are
produced.

## 1. Problem definition

Given a review sentence, produce a set of pairs *(aspect term, sentiment)*,
where the aspect term is a span of the sentence naming a feature of the product
and the sentiment is positive, negative or neutral. This is solved as two
sub-tasks:

1. **Aspect term extraction (ATE)**: sequence labelling.
2. **Aspect sentiment classification (ASC)**: sentence-pair classification.

## 2. Dataset

**SemEval-2014 Task 4: Aspect Based Sentiment Analysis** (Pontiki et al., 2014),
the standard benchmark for this task. It contains customer-review sentences from
two domains, laptops and restaurants. Every sentence is annotated by humans with
its aspect terms, their character offsets and their polarity.

`training/prepare_dataset.py` downloads the original XML files, validates them
and writes the splits. Counts after preparation (from
`data/processed/dataset_stats.json`):

| Split | Source | Laptops sentences | Restaurants sentences | Aspect terms (both) |
|---|---|---|---|---|
| train | 90% of official training data | 2723 | 2726 | 5453 |
| val | 10% of official training data | 303 | 303 | 577 |
| test | official gold test set, unchanged | 800 | 800 | 1788 |

Validation performed by the script:

- aspect offsets must lie inside the sentence; polarity must be a known value;
- duplicate annotations of the same span are dropped;
- **leakage check**: the official files are not perfectly disjoint. Two training
  sentences also occur in the gold test set and 29 training sentences are exact
  duplicates of others. These are removed from the training data (the test set
  is never modified), and the script fails if any sentence text is shared
  between splits;
- the train/validation split is by sentence, per domain, with a fixed seed (42).

Polarity `conflict` (an aspect that is both praised and criticised; 126 of the
5453 training terms) is kept for aspect extraction but excluded from sentiment
classification, which is the usual 3-class setting.

**Which data the shipped models use.** All three deployed models are trained
on both domains. The "Training setup" table in `results.md` lists, for each
model, the domains it was trained on and every hyperparameter; the same
information is served by `GET /api/model-info`. Earlier models trained on
laptops only are kept for the transfer study in [transfer.md](transfer.md).

## 3. Preprocessing

Implemented in `backend/app/nlp/preprocessing.py` and used identically for
training and inference.

| Step | What is done | Why |
|---|---|---|
| Cleaning | Unicode NFKC, HTML tags/entities and control characters removed, whitespace collapsed | Remove noise without changing words |
| Sentence segmentation | NLTK Punkt | The models are trained on single sentences |
| Word tokenisation | Words and single punctuation marks, each with character offsets | Labels are per word; offsets map predictions back to the text |
| Lowercasing | Done by the `bert-base-uncased` tokenizer | Matches the pretrained vocabulary |
| Sub-word tokenisation | BERT WordPiece | "touchpad" -> "touch", "##pad" |
| Stop-word removal / stemming | **Not applied** | BERT is contextual; "not good" must not become "good" |
| Lemmatisation | WordNet, only to group aspects in statistics | "batteries" and "battery" should count together |

### BIO label conversion

Annotated character spans become one tag per word:

```
The   battery    life       is  great  but  the  screen     is  dim  .
O     B-ASPECT   I-ASPECT   O   O      O    O    B-ASPECT   O   O    O
```

`B-ASPECT` starts an aspect, `I-ASPECT` continues it, `O` is everything else.
The B/I distinction keeps adjacent aspects separate.

### Aligning word labels with WordPiece tokens

BERT may split one word into several pieces, but there is one label per word.
The first piece keeps the word's label; the other pieces and the special tokens
get the label `-100`, which the loss function ignores:

```
pieces : [CLS]  the  touch     ##pad  is  great  [SEP]
labels : -100   O    B-ASPECT  -100   O   O      -100
```

At prediction time a word takes the prediction of its first piece.

## 4. Models

Three models are trained. All start from the pretrained `bert-base-uncased`
encoder (12 layers, hidden size 768) and are fine-tuned end to end.

| Model | Folder | Task | Role |
|---|---|---|---|
| Aspect extraction | `models/aspect_extraction` | token classification | ABSA stage 1 |
| Aspect sentiment | `models/sentiment` | sentence-pair classification | ABSA stage 2 |
| Overall sentiment | `models/overall_sentiment` | single-sentence classification | the traditional baseline |

### 4.1 Aspect extraction: BERT token classifier

`[CLS] w1 ... wn [SEP]` -> BERT -> a linear layer on every token's hidden state
-> 3 classes (`O`, `B-ASPECT`, `I-ASPECT`). Loss: cross-entropy over the labelled
tokens. Consecutive aspect tags are merged into one multi-word aspect.

### 4.2 Aspect sentiment: BERT sentence-pair classifier

Input `[CLS] sentence [SEP] aspect [SEP]`; a linear layer on BERT's `[CLS]`
representation outputs 3 classes; the label is the gold polarity of that
aspect. Because the aspect is part of the input, the same sentence can yield
different predictions for different aspects. This is the "BERT-SPC"
formulation.

### 4.3 Overall sentiment: BERT single-sentence classifier (baseline)

Input `[CLS] sentence [SEP]`, same classification head. This is ordinary
sentiment analysis, kept so that the interface can show "traditional" next to
"aspect-based". SemEval-2014 has no sentence-level sentiment annotation, so the
training label is a *weak* label derived from the sentence's aspect polarities:
positive if positive aspects outnumber negative ones, negative in the opposite
case, neutral on a tie. Sentences without aspect annotations have no label and
are not used. For a multi-sentence review, the per-sentence class probabilities
are averaged.

**Why two sentiment models instead of one.** The first version of this project
trained a single classifier on both kinds of input. Its accuracy on test
aspects was 0.7743 overall, but only 0.5049 on aspects in *mixed* sentences
(sentences whose aspects have different polarities; 103 aspects) against 0.8262
in uniform ones (535 aspects). Training the model to also output the sentiment
of the whole sentence encourages it to ignore which aspect it was asked about.
The two tasks were therefore separated. (Those figures describe that first
laptops-only model; they are kept here as the reason for the design and are not
part of the generated results.) `results.md` reports the mixed/uniform
breakdown for the deployed model, so this weakness stays visible.

### 4.4 Context identification

For display, each aspect is shown with the clause it occurs in, found by
splitting the sentence at punctuation and contrastive conjunctions ("but",
"however", "although", ...). The classifier itself receives the *whole*
sentence, not only this clause, so that it can use information from elsewhere in
the sentence (negation, comparisons).

## 5. Training

`training/common.py: fine_tune` is a plain PyTorch loop:

- AdamW, weight decay 0.01 (none on biases and LayerNorm weights);
- linear warm-up over the first 10% of steps, then linear decay to zero;
- gradient clipping at norm 1.0;
- batch size 16, maximum 128 word-pieces, dynamic padding, length bucketing;
- learning rate 3e-5 (aspect extraction) and 2e-5 (both sentiment models);
  the number of epochs of each run is in `results.md`;
- fixed random seed (42);
- **model selection on the validation split** after every epoch (span F1 for
  aspect extraction, macro-F1 for sentiment); only the best checkpoint is kept.
  The test set is never used during training.

Each model directory contains `training_log.json` with the hyperparameters, the
loss and validation score of every epoch, and the training time.

## 6. Evaluation

`training/evaluate.py`, on the official gold test set.

| Evaluation | Metric | Definition |
|---|---|---|
| Aspect extraction | Precision, recall, F1 | Exact match: a predicted aspect is correct only if both boundaries equal the annotation. Micro-averaged over all aspects. |
| Aspect sentiment | Accuracy; macro and per-class precision, recall, F1; confusion matrix | Gold aspects are given, so this measures the classifier alone. |
| Aspect sentiment by sentence type | Accuracy, macro-F1 | Separately for aspects in *uniform* sentences (all aspects share a polarity) and *mixed* sentences (they differ). Only the mixed subset shows whether predictions are truly aspect-specific. |
| Overall sentiment | Same as aspect sentiment | Against the weak sentence labels of section 4.3. |
| Baseline | All of the above | A rule-and-lexicon system scored by the same functions, see [baseline.md](baseline.md). |
| Error analysis | Error types, confusions, accuracy by confidence | See [error_analysis.md](error_analysis.md). |
| End-to-end ABSA | Precision, recall, F1 | Raw sentence in; a predicted (aspect, sentiment) pair is correct only if span and sentiment are both right. |

Macro-F1 is reported next to accuracy because the classes are imbalanced
(positive is the largest class), and accuracy alone would hide weak performance
on the neutral class.

## 7. Limitations

- Trained on laptop/restaurant reviews from 2014. Aspects of other product
  types are extracted only as far as the model generalises from context.
- Only explicit aspects (words present in the text) are found. "It dies after
  two hours" implies *battery* but contains no aspect term.
- The sentiment input identifies an aspect by its text. If the same aspect term
  occurs twice in one sentence with different sentiments, both get the same
  prediction.
- Overall-sentiment labels are derived, not annotated (section 4.3).
- Sentences that mix sentiments are the hardest case and are rare in the
  training data; see the mixed-sentence row in `results.md`.
- Results come from one training run with one seed; no confidence intervals.
- The deployed models were chosen over the previous ones by comparing test-set
  scores on both domains (`training/promote.py`), a mild use of the test set
  for selection.
- "Confidence" is the softmax probability of the predicted class. It is not
  calibrated and should be read as a relative score.

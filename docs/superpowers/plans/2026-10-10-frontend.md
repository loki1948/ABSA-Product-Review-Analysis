# Frontend Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the JSON-printing scaffold with the complete interface: review analysis, history, dashboard, batch upload and model performance, with every backend state handled.

**Architecture:** Pure helpers in `src/lib` (unit-tested), presentational components in `src/components` that receive data through props, and pages in `src/pages` that own the API calls through the existing `src/services/api.ts`.

**Tech Stack:** React 19, TypeScript (strict), Vite, Tailwind CSS 4, Recharts, React Router; Vitest, jsdom and React Testing Library for tests.

**Spec:** `docs/superpowers/specs/2026-10-09-frontend-design.md`

## Global Constraints

- No new runtime dependency. Dev dependencies only: `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`.
- No `fetch` outside `src/services/api.ts`. The backend API does not change.
- Sentiment is never conveyed by colour alone: a text label accompanies every coloured element.
- Review length limit 5000 characters; batch chunk size 10; batch file limit 500 reviews; history page size 10; dashboard shows the top 10 aspects.
- `npm run build` (type-check + build) and `npm test` pass at the end of every task.
- Each task: tests first, watch them fail, implement, watch them pass, commit.
- While model training is running on this machine, run Vitest with `--no-file-parallelism`.

## Review Focus

1. Aspect offsets that are out of range or overlap (a stored review edited by hand, or a future backend bug): `HighlightedReview` must render the plain text, not crash. Test in Task 2.
2. A CSV exported from Excel: UTF-8 byte-order mark, `\r\n` line ends, quoted fields containing commas and newlines. Test in Task 2.
3. An evaluation report in the old layout (no per-domain scopes, no mixed-sentence section), which is what `/api/model-info` returns today. The card must show "n/a", not break the Dashboard. Test in Task 2.
4. Deleting the only review on the last history page: the page must step back, not show an empty table with "21–20 of 20". Test in Task 6.
5. A batch run whose third chunk fails: the first twenty results stay on screen and can be exported. Test in Task 8.

### Task 2: Pure helpers (`src/lib`)

**Files:** create `sentiment.ts`, `highlight.ts`, `csv.ts`, `modelReport.ts` and a `.test.ts` beside each.

**Interfaces (produced):**
- `sentiment.ts`: `SENTIMENTS: Sentiment[]` (`positive`, `neutral`, `negative`); `sentimentLabel(s): string`; `badgeClass(s): string`; `chartColor(s): string`; `percent(value: number): string` (`0.954 -> "95%"`).
- `highlight.ts`: `type Segment = { text: string; aspect: AspectResult | null }`; `segments(review: string, aspects: AspectResult[]): Segment[]` — concatenating every `text` gives `review`; aspects with `start < 0`, `end > review.length`, `start >= end` or overlapping an earlier aspect are dropped.
- `csv.ts`: `parseReviews(text: string): { reviews: string[]; skipped: { line: number; reason: string }[]; truncated: boolean }`; `parseCsvRows(text: string): string[][]`; `toCsv(items: AnalysisResponse[]): string`; constants `MAX_REVIEW_CHARS = 5000`, `MAX_BATCH_FILE_REVIEWS = 500`.
- `modelReport.ts`: `type ScopeMetrics = { scope: string; testSentences: number | null; aspectF1, aspectPrecision, aspectRecall, sentimentAccuracy, sentimentMacroF1, mixedAccuracy, overallAccuracy, overallMacroF1, endToEndF1: number | null }`; `readReport(report: Record<string, unknown>): { generatedAt: string | null; domains: string[]; scopes: ScopeMetrics[] }`.

- [ ] Tests per spec section 5 (rows `highlight.ts`, `csv.ts`, `modelReport.ts`) plus Review Focus 1–3. Implement. Commit.
